# PolicyVersionRegistry

`PolicyVersionRegistry` is BookGuard's planned second Base Mainnet contract. It provides immutable, public provenance for the versioned risk policies used by a bot or analysis service.

> **Deployment status:** Implemented and locally tested; **not deployed**. No address, transaction, or wallet approval exists yet.

## What it records

For each policy namespace and version, the contract records:

- `policyId` — a `bytes32` policy namespace;
- `version` — a positive `uint64` version number;
- `contentHash` — keccak-256 hash of canonical policy JSON;
- `publisher` — the Base address that first claimed the namespace;
- `publishedAt` — Base block timestamp.

`registerPolicyVersion(bytes32,uint64,bytes32)` is immutable: the same `(policyId, version)` cannot be overwritten. The address that first publishes a `policyId` is the only address that can append later versions in that namespace.

## Canonical namespace and content inputs

The dependency-free helper `web/policy-version.mjs` creates the recommended inputs:

```text
policyId    = keccak256("bookguard:policy-namespace/v1:" + lowercasePublisher + ":" + lowercaseSlug)
contentHash = keccak256(canonicalJson(policyObject))
```

Including the publisher address in `policyId` prevents collision between similarly named policies from different publishers. It does **not** establish that the publisher is a human, company, approved strategy, or trusted source; consumers must apply their own allowlist or trust policy.

Example policy body:

```json
{"maxSpreadBps":125,"minVisibleDepthUsd":500,"staleAfterSeconds":10}
```

## Read operations

```solidity
getPolicyPublisher(bytes32 policyId) returns (address)
getPolicyVersion(bytes32 policyId, uint64 version) returns (bytes32 contentHash, address publisher, uint64 publishedAt)
```

An empty return struct means that version has not been registered.

## Deliberate non-goals

This registry does not:

- evaluate policy thresholds or market conditions;
- assert policy quality, expected returns, market outcomes, or profitability;
- accept funds, tokens, fees, approvals, custody, or escrow;
- place, route, cancel, or otherwise manage orders;
- support proxy upgrades, admin backdoors, token issuance, or publisher recovery.

A lost publisher key means no additional version can be added under its existing namespace. That is intentional for this minimal immutable v1; create a new publisher-scoped namespace rather than adding privileged recovery behavior.

## Mainnet deployment gate

Before any Base Mainnet broadcast:

1. Run a dry-run and inspect exact compiler settings, bytecode, target chain (`8453`), constructor arguments (none), estimated gas and value (`0 ETH`).
2. Review the canonical policy preview and calldata generated by `web/policy-version.mjs`.
3. Onur reviews the wallet confirmation screen: signer, Base Mainnet, new contract bytecode, value and gas.
4. Only after explicit approval: broadcast, verify exact source on BaseScan, record the address/transaction in `DEPLOYMENTS.md`, and refresh Guild Verify.
